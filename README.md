## Санхүүгийн үндсэн зарчим

Үлдэгдлийг **багана болгож хадгалахгүй**. Үргэлж дараах томьёогоор бодно:

```
үлдэгдэл = Σ(нэхэмжлэл) − Σ(хуваарилалт)

эерэг = өртэй       сөрөг = илүү төлсөн       0 = цэвэр
```

Үүний ач холбогдол:

* Үлдэгдэл **зөрөх техникийн боломжгүй** — тооцоолол нэг л газар байна
* **Буцаах** нь үнэгүй ирнэ: буруу хуваарилалтыг устгахад үлдэгдэл өөрөө засагдана
* Илүү төлөлт дараа сарын нэхэмжлэлээс **автоматаар хасагдана** (тусдаа код хэрэггүй)

Жишээ: 50,000₮ нэхэмжилж 70,000₮ төлсөн → үлдэгдэл `−20,000`.
Дараа сар 50,000₮ нэхэмжлэхэд үлдэгдэл `50,000 + (−20,000) = 30,000` болно.

## Ус, дулааны тооцоолол

Excel дээр гараар бодохын оронд **систем өөрөө бодно**. Импортлоход зөвхөн
4 заалт уншина — зөрүү, төлбөр, НӨАТ багануудыг үл хэрэгсэнэ.

```
халуун зөрүү = халуун одоо − халуун өмнөх
хүйтэн зөрүү = хүйтэн одоо − хүйтэн өмнөх
нийт м³      = халуун + хүйтэн

PER_M3  мөрүүд = нийт м³ × тариф     (цэвэр ус, бохир ус)
FIXED   мөрүүд = тариф               (суурь хураамж, ус халаалт)
─────────────────────────────────────
дэд дүн        = дээрхийн нийлбэр
PERCENT мөрүүд = дэд дүн × хувь      (НӨАТ)
нийт төлбөр    = дэд дүн + НӨАТ      → invoices.bill_amount
```

Тариф `/admin/tariffs` цэсэнд. **Засахгүй — солино**: хуучин мөр огноогоор
хаагдаж, шинэ мөр үүснэ. Ингэснээр өнгөрсөн сарын нэхэмжлэл хуучин
тарифаараа тайлбарлагдсан хэвээр үлдэнэ.

`invoices.breakdown` (jsonb) дотор мөр бүрийн **тухайн үеийн тариф** хадгалагдана.
Оршин суугч «Төлбөр хэрхэн бодогдсон бэ?» гэдгийг дэлгэж харна.

### Excel-ийн онцлог

Баганын нэрэнд сар бичигдсэн байдаг («Халуун ус 9 сар заалт») бөгөөд сар бүр
өөрчлөгдөнө. Тиймээс **нэрээр биш байрлалаар** ялгана: `халуун` + `заалт`
агуулсан хоёр багана — зүүн нь өмнөх, баруун нь одоогийн.

Толгой нь **хоёр мөр** байж болно (дээр «Заалт», «Цэвэр ус» гэх бүлгийн нэр).
`findHeaderRow()` зангуу үгээр нь жинхэнэ толгойг өөрөө олно.

**Орц бүр тусдаа таб** («9 сар 1 орц», «9 сар 2 орц»). Бүх табыг НЭГТГЭЖ
оруулна — тоот байр даяар unique тул орц тулгалтад хамаагүй. Файлаа 2 удаа
оруулах шаардлагагүй. Нэг тоот хоёр табад давхардвал бүртгэхээс **татгалзана**.

**Нэрээр бичигдсэн хэсгүүд** («amo sport», «дэлгүүр») — `flats.excel_label`
багананд Excel дээрх бичиглэлийг хийвэл танина. `owner_name` нь оршин суугчид
харагддаг нэр, `excel_label` нь импортын түлхүүр — хоёр өөр зорилготой.

⚠️ «өмнө сарууддын үлдэгдэл», «Нийт төлбөр» багануудыг **оруулахгүй** —
үлдэгдлийг систем `Σнэхэмжлэл − Σхуваарилалт`-аар өөрөө бодно. Оруулбал
давхар тоологдоно.

```bash
npm run test:water   # 2 мөрт толгойтой жинхэнэ хүснэгт дээр бүх гинжийг шалгах
```

## Цахилгааны тооцоолол

Нэг тоолуур, гэхдээ хоёр бүрэлдэхүүн — хэрэглэсэн эрчим хүч, дээр нь дундаж
**чадлын** төлбөр.

```
зөрүү         = заалт(энэ сар) − заалт(өмнөх сар)
квт·ц         = зөрүү × LOSS_COEF               (1.025 — сүлжээний алдагдал)
эрчим хүч     = квт·ц × ENERGY_RATE             (265 ₮/кВт·ц)

дундаж чадал  = квт·ц ÷ DAYS ÷ HOURS            (31 хоног, 12 цаг)
чадлын төлбөр = дундаж чадал × CAPACITY_RATE    (15,500 ₮/кВт)
──────────────────────────────────────────────
нийлбэр       = эрчим хүч + чадлын төлбөр
нийт          = нийлбэр × (1 + VAT)             → invoices.bill_amount
```

`DAYS`, `HOURS` нь `NUMBER` төрлийн тариф — **мөнгө биш**, чадлын томьёоны
хуваарь. Бусадтай адил `/admin/tariffs` цэсээс засна.

Дунд алхамд дугуйруулахгүй, зөвхөн эцсийн дүнг 2 орон хүртэл дугуйруулна —
Excel-тэй яг таарахын тулд.

```bash
npm run test:electricity   # Жинхэнэ хүснэгтийн бүтэц дээр бүх гинжийг шалгах
```

## Тулгалтын урсгал

```
Excel хуулга
   │  (браузер дээр SheetJS уншина → Vercel-ийн 10 сек хязгаарт ойртохгүй)
   ▼
POST /api/admin/reconcile/preview     ← DB-д ЮУ Ч БИЧИХГҮЙ
   │  · Зарлага мөрийг бүрэн алгасна
   │  · Тоот таана → flats-тай тулгана
   │  · Давхардсан гүйлгээг илрүүлнэ
   │  · Илүү төлөлт үүсэхийг урьдчилж анхааруулна
   ▼
Админ хараад баталгаажуулна
   ▼
POST /api/admin/reconcile/commit      ← Түүхий мөрийг СЕРВЕР дээр дахин задлана
   │  · transactions руу бичнэ (dedupe_hash UNIQUE)
   │  · Тоот эргэлзээгүй олдсоныг автоматаар хуваарилна
   ▼
Үлдсэнийг админ гараар: POST /api/admin/allocations
```

### Тоот таних алгоритм

Энгийн regex хангалтгүй — нэг утганд 3 тоо байж болно:

```
"323р байр 1 орц 127 тоот"   →  323? 1? 127?
"12-2-278 DULAAN"            →  12? 2? 278?
```

Тиймээс 2 үе шаттай:

1. **Дуут үг хасах** — `N сар`, `N орц`, `N байр`, 7+ оронтой тоо (утас/данс)
2. **Нэр дэвшүүлэх** — зэрэглэлтэйгээр:
   | Зэрэглэл | Хэв маяг | Жишээ |
   |---|---|---|
   | 1 | `ТООТ` үгийн өмнөх тоо | `127 тоот` |
   | 2 | зураасан гинжний сүүлийн тоо | `12-2-**278**` |
   | 3 | эхэнд байгаа тоо + нэр | `292-ГАНХУЯГ` |
   | 4 | бусад тусдаа тоо | |
3. **Баталгаажуулах** — `flats` хүснэгтэд байгаа тоотуудтай тулгана.
   Яг нэг үлдвэл → автомат. 0 эсвэл 2+ үлдвэл → **гар шалгалт**.

Латин/кирилл холилдсоныг тэмдэгтийн ангиар шийдсэн: `8CAP` (латин C-A-P) = `8САР`.

**Одоогийн үр дүн: жинхэнэ хуулгын 20/20 мөр зөв (100%).**

## Аюулгүй байдал

* Оршин суугчийн дэлгэц Supabase руу **шууд хандахгүй**. Бүх дата Server
  Component-оор дамжина → браузер руу key огт очихгүй, зөвхөн тухайн тоотын дата очно.
* Бүх хүснэгтэд **RLS асаалттай**, зөвхөн нэвтэрсэн админ хандана.
* `commit` клиентээс ирсэн задлан шинжилгээнд **найдахгүй** — сервер дээр дахин задална.
* `dedupe_hash` дээрх UNIQUE индекс нэг файлыг олон удаа оруулахаас хамгаална.
* Trigger хуваарилалтын нийлбэрийг гүйлгээний дүнгээс хэтрүүлэхгүй.

## Админ хэсэг

Хаяг үүсгэх: Supabase → **Authentication → Users → Add user** (и-мэйл + нууц үг).
Бүртгүүлэх дэлгэц ЗОРИУД байхгүй — гаднаас хэн ч хаяг үүсгэж чадахгүй.

Нэвтрэх: <http://localhost:3000/admin> → login руу аяндаа чиглүүлнэ.

| Дэлгэц | Хийдэг зүйл |
|---|---|
| `/admin` | Хяналтын самбар — гар шалгалтын тоо, нийт өр |
| `/admin/announcements` | Зарлал нэмэх, нуух, онцлох, устгах |
| `/admin/invoices` | Нэхэмжлэлийн Excel импорт (preview → commit) |
| `/admin/tariffs` | Тариф солих — ус дулааны тооцооллын тогтмол утгууд |
| `/admin/reconcile` | Хуулгын Excel тулгалт + гар оноолт |

Хамгаалалт **хоёр давхар**: `middleware.ts` (чиглүүлэлт) ба
`admin/(panel)/layout.tsx` дотор `requireAdmin()` (дахин шалгалт). Зөвхөн
middleware-т найдвал шинэ route нэмэхэд мартах эрсдэлтэй.

### Excel-ийн толгой мөр

Багана таних нь нэрээр ажиллана — дараалал хамаагүй, нэмэлт багана байж болно.

| Файл | Заавал | Байвал уншина |
|---|---|---|
| Нэхэмжлэл | `Тоот`, `Дүн` | `Өмнөх заалт`, `Одоогийн заалт`, `Зарцуулалт`, `Тайлбар` |
| Банкны хуулга | `Орлого`* , `Гүйлгээний утга` | `Гүйлгээний огноо`, `Эцсийн үлдэгдэл`, `Харьцсан данс` |

\* Банк болгон өөрөөр бичдэг тул **3 хэлбэрийг** дэмжинэ:

| Хуулгын хэлбэр | Зарлагыг хэрхэн ялгах вэ |
|---|---|
| `Орлого` / `Зарлага` тусдаа багана | Орлого хоосон мөрийг алгасна |
| `Кредит` / `Дебит` тусдаа багана | Мөн адил |
| Нэг `Гүйлгээний дүн` багана | **Тэмдгээр** — сөрөг тоо = зарлага |

Зарлага (шимтгэл, шилжүүлэг, цалин) `transactions` хүснэгтэд **огт орохгүй**.
Preview дэлгэц дээр «Бүртгэхгүй N мөр» хэсгийг дэлгэж шалтгаан бүрийг харна.

Нэг сарыг ДАХИН оруулбал хуучин нэхэмжлэлийг **дарж бичнэ** (upsert) —
буруу файл оруулсныг засах боломжтой. Төлбөр (хуваарилалт) хөндөгдөхгүй.

```bash
npm run test:statement  # Зарлага ялгах логикийг 3 хэлбэр дээр шалгах
npm run test:invoices   # Нэхэмжлэлийн Excel задлагчийг шалгах
```
